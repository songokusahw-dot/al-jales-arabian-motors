# حزمة توجيهات Lovable — AL-JALES AUTOMOTIVE

**الإصدار:** 1.0 — 7 نوفمبر 2026  
**اللغة:** التوجيهات بالعربية، مع الإبقاء على أسماء المكتبات والملفات والمصطلحات التقنية بالإنجليزية.

## لماذا هذه الحزمة؟

هذه الحزمة ليست Prompt واحداً ضخماً. إنها نظام توجيه مقسّم إلى:

1. `PROJECT_INSTRUCTIONS.txt`: قواعد المشروع الدائمة التي تلصقها في إعدادات المشروع داخل Lovable.
2. `AGENTS.md`: قواعد المطور التي توضع في جذر مستودع المشروع، ويقرأها Lovable مع الطلبات.
3. `prompts/`: أوامر تنفيذ مستقلة ومرتبة؛ يُرسل كل أمر في رسالة مستقلة.
4. `docs/`: قرارات ثابتة عن المسارات، الألوان، البيانات، الحزم والاختبارات.

## طريقة الاستخدام — بالترتيب

### أ. تثبيت التعليمات الدائمة

1. افتح مشروع AL-JALES الصحيح داخل Lovable.
2. افتح **Project settings → Instructions**.
3. انسخ محتوى `PROJECT_INSTRUCTIONS.txt` كاملاً والصقه. الحد الموثق الحالي لتعليمات المشروع 10,000 حرف؛ الحزمة صممت لتبقى دون هذا الحد.
4. أضف `AGENTS.md` في جذر المشروع (Root). لا تضعه داخل `src/` فقط؛ المطلوب هنا الملف الجذري.
5. لا تضع قواعد AL-JALES في Workspace Instructions العامة؛ فهي خاصة بهذا المشروع، بينما Workspace Instructions تؤثر في مشاريع أخرى ضمن مساحة العمل.

### ب. ابدأ بالتدقيق قبل البناء

1. افتح `prompts/00_INSPECT_CURRENT_PROJECT.md`.
2. أرسل النص في **Plan mode** وليس Build mode.
3. اطلب تقريراً عن المشروع الفعلي: الإطار، المسارات، الملفات، المكتبات، الأصول، حالة Git، وما هو موجود وما هو ناقص.
4. يجب ألا يغيّر Lovable أي ملف في المرحلة 00. راجع التقرير أولاً.

### ج. التنفيذ المرحلي

بعد مراجعة التقرير، أرسل الأوامر التالية في **Build mode**، كل واحد على حدة:

- `01_FOUNDATION_AND_ROUTING.md`
- `02_HOMEPAGE_HERO_BRANDS_MARQUEE.md`
- `03_INVENTORY_SEARCH_FILTERS.md`
- `04_VEHICLE_DETAIL_GALLERY_PRICING_INSPECTION.md`
- `05_MARKETS_SHOWROOMS_AUCTIONS.md`
- `06_FORMS_CONTENT_REVIEWS_CONTACT.md`
- `07_RESPONSIVE_MOTION_ACCESSIBILITY_PERFORMANCE.md`
- `08_FINAL_QA_ACCEPTANCE.md`

لا ترسل جميع المراحل في رسالة واحدة. بعد كل مرحلة افحص Preview، راجع الملفات المتغيرة، ثم انتقل إلى المرحلة التالية.

## قرارات Lovable الحديثة التي بُنيت عليها الحزمة

- **Instructions** دائمة؛ **Skills** تُحمّل عند الحاجة. لهذا المشروع استُخدمت تعليمات المشروع و`AGENTS.md` للقواعد الدائمة، وأوامر Markdown منفصلة للمراحل. لا نحتاج Skill عامة في Workspace لمشروع واحد.
- يستخدم Lovable حالياً **Plan / Chat / Build**. استخدم Plan للتدقيق والتحليل دون تعديل، وBuild لتنفيذ المراحل.
- المشاريع الجديدة على Lovable تعتمد حالياً **TanStack Start** مع SSR؛ المشاريع الأقدم قد تستخدم React/Vite أو بنية مختلفة. لا تفرض إعادة إنشاء المشروع أو تغيير الإطار. اعمل مع الموجود، وإذا كان المشروع فارغاً تماماً فاحترم قالب Lovable الحالي.
- مع SSR، يجب ألا تُنفّذ `window` أو `document` أو تهيئة GSAP/Lenis/Embla عند تقييم الوحدات على الخادم. نفّذها داخل client lifecycle المناسب وبعد mount.
- Lovable يقرأ `AGENTS.md` أو `CLAUDE.md` من جذر المشروع مع كل رسالة، ويمكنه قراءة ملفات تعليمات فرعية عند العمل داخل المجلدات المعنية.

## حزمة المكتبات المقترحة — لا تثبّت عشوائياً

| الاستخدام | القرار |
|---|---|
| إطار العمل والراوتر | حافظ على الموجود. TanStack Start/TanStack Router للمشروعات الجديدة الحالية إذا كان هذا ما أنشأه Lovable. لا تستبدل React/Vite في مشروع قائم. |
| Scroll-driven motion | GSAP + ScrollTrigger + `@gsap/react` للمشاهد السينمائية المرتبطة بالتمرير فقط. |
| تفاعلات الواجهة | `motion` مع `motion/react`، أو المكتبة الموجودة فعلاً إذا كانت `framer-motion` مستخدمة؛ لا تثبّت المكتبتين معاً بلا داعٍ. |
| Smooth scrolling | Lenis اختياري، طبقة واحدة فقط، ولا يعيق التمرير الطبيعي. إذا سبّب تعارضاً مع SSR أو ScrollTrigger فاترك التمرير الأصلي. |
| شريط العلامات | `embla-carousel-react` + `embla-carousel-auto-scroll` من خط v8 المستقر، فقط إذا لم توجد مكتبة مكافئة مناسبة في المشروع. |
| Icons | استخدم الموجود، أو Lucide إن كان مثبتاً/مناسباً. أيقونات الشبكات الاجتماعية تكون Inline SVG داخل مكونات داخلية. |

**مبدأ تثبيت الحزم:** افحص `package.json` وملف القفل أولاً. لا تكرر مكتبة موجودة. ثبّت فقط ما تحتاجه المرحلة الحالية. لا تستخدم Embla v9 RC للمشروع ما دام v8 المستقر كافياً، ولا تخلط major versions بين Embla Core وReact وAuto Scroll.

## معلومات يجب ألا يخترعها الموقع

- الهاتف، WhatsApp، البريد، عناوين الفروع، الإحداثيات، أسماء الشركاء الكوريين، تقييمات العملاء، تقارير الفحص، الأسعار الحقيقية، أو توفر السيارة.
- القيم الناقصة تُدار كـ `null` ويُعرض بديل عربي صريح مثل «سيتم إضافة بيانات التواصل» أو نموذج التواصل.
- لا تُظهر زر WhatsApp كرابط صالح إلا عند وجود رقم صحيح في إعدادات الموقع.
- الطلبات والتقييمات والأسئلة في النسخة الحالية محاكاة محلية فقط؛ يجب أن تقول الواجهة بوضوح: «نموذج تجريبي — لم يتم إرسال البيانات إلى الشركة».

## مسارات المشروع المختارة

راجع `docs/ROUTE_MAP_AR.md`. أهم قاعدة: صفحات كوريا والسعودية واليمن تستخدم مكوّناً واحداً لقائمة السيارات مع `market` مختلف، وصفحة التفاصيل لها مسار منفصل `/car/:slug` لتجنب تعارضه مع `/cars/korea`.

## العملات وقواعد التسعير

- عملة العرض والبيع الافتراضية للموقع هي **الريال السعودي SAR** في الأسواق الثلاثة إلى أن يزوّد صاحب المشروع بقرار مختلف.
- سعر التحويل `0.00275 SAR لكل KRW` قيمة تجريبية معتمدة في البرومبت السابق، وليست سعر صرف حيّاً ولا يجوز تقديمها كقيمة سوقية حالية.
- احفظ قيمة المصدر KRW في البيانات الكورية عند الحاجة، لكن اعرض مبالغ التكاليف النهائية في الواجهة بعملة البيع SAR فقط.
- يجب أن يكون كل عنصر في تفصيل السعر قابلاً للتتبع إلى حقل بيانات؛ إن كانت القيمة غير معروفة فلا تخترعها ولا تدخلها في الإجمالي.

## الصور والشعارات

- استخدم صور سيارات حقيقية موثوقة ومطابقة للطراز المعروض من ملفات الشركة أو مصدر مرخّص/رسمي.
- **ممنوع توليد صور سيارات بالذكاء الاصطناعي**؛ صور السيارات يجب أن تمثل السيارة الحقيقية أو تكون موسومة صراحةً «صورة توضيحية غير ممثلة للمركبة».
- يمكن توليد أو تصميم صور أجواء مجردة لا تحتوي على سيارات أو شعارات أو لوحات أرقام أو ادعاء بأنها صورة معرض فعلي.
- إذا لم يوجد شعار علامة حقيقي، اعرض اسم العلامة كنص أنيق؛ لا ترسم شعاراً تقريبياً.
- اجمع مسارات الصور وحقوق المصدر وAlt text في ملف مركزي، واستخدم Placeholder واضحاً عند فقد الصورة.

## لا تضف تتبعاً دون موافقة

لا تضف Google Analytics أو Meta Pixel أو TikTok Pixel أو session replay أو tracking cookies في هذه النسخة. لا تجمع أحداثاً شخصية. يمكن إضافة analytics لاحقاً بعد موافقة صريحة، وتعريف سياسة الخصوصية والموافقة المناسبة.

## متى تعتبر المرحلة مكتملة؟

لا تكتفِ بإنشاء ملفات أو كتابة تقرير. يجب أن تعمل الصفحات والروابط والتفاعلات ضمن نطاق المرحلة، وأن تذكر الملفات التي تغيرت، وما اختبرته، ونتائج الاختبار، والعناصر التي بقيت Placeholder.
