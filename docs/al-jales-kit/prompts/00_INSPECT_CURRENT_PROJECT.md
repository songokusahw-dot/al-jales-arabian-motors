# المرحلة 00 — تدقيق المشروع قبل أي تعديل

**الوضع المطلوب: Plan mode فقط. لا تستخدم Build في هذه المرحلة.**

أريد تدقيقاً فعلياً لمشروع AL-JALES المفتوح حالياً في Lovable. لا تكتب أو تعدل أو تنشئ أو تحذف أي ملف في هذه المرحلة.

## 1. اقرأ التعليمات والأصول أولاً

- اقرأ Project Instructions وملف `AGENTS.md` و`CLAUDE.md` إن كان موجوداً.
- افحص جذر المشروع وكل مجلدات التطبيق ذات الصلة.
- افحص `package.json` وlockfile وملفات إعداد TypeScript وTailwind وVite/Router/TanStack Start وأي إعداد shadcn/ui.
- افحص الراوتر والمسارات الحالية، ملفات CSS العامة وCSS variables، المكونات المشتركة، الخطوط، الصور، الشعارات، الأيقونات، ملفات البيانات والخدمات.
- افحص `git status` وdiff والملفات المتتبعة إن كان Git متاحاً. اذكر التعديلات الموجودة قبل لمسك لأي ملف.

## 2. حدّد التقنية الفعلية

أخبرني هل المشروع:
- TanStack Start / TanStack Router مع SSR؛
- React + Vite؛
- Next.js؛
- أو إطار آخر.

لا تفترض أن مشروع Lovable الحالي فارغ أو أنه يستخدم Vite. لا تقترح ترقية إطار العمل لمجرد أن Lovable يستخدم TanStack Start للمشاريع الجديدة. حافظ على مشروع قائم كما هو.

## 3. جرد الحزم

أنشئ جدولاً بثلاث فئات:
1. مثبتة وتُستخدم فعلياً.
2. مثبتة لكن لم تجد استخداماً واضحاً لها.
3. غير مثبتة وقد نحتاجها لاحقاً.

تحقق تحديداً من وجود:
- GSAP وScrollTrigger و`@gsap/react`.
- `motion` أو `framer-motion` (لا تفترض الحاجة إلى الاثنين).
- Lenis.
- `embla-carousel-react` و`embla-carousel-auto-scroll` أو بديل Carousel قائم.
- Lucide أو مكتبة الأيقونات المستخدمة.

لا تثبّت شيئاً في هذه المرحلة. وضّح ما إذا كان اختيار الحزمة مناسباً وما الذي يستخدمه كل Package، وسجّل أي تكرار أو تعارض أو package غير مستخدم.

## 4. جرد المراجع والتصميم

- تحقق من وجود ملفات مراجع AL-JALES الحديثة، مثل مراجع ARCO أو ملفات الأكواد/الصور أو `reference-assets`.
- افصل بين المراجع الموجودة فعلياً والمراجع التي ذُكرت في المستندات فقط.
- المرجع الأحدث المعتمد هو الحاكم. النمط المطلوب Light افتراضياً مع Dark toggle فعلي، ولا تعِد اتجاه Obsidian/Champagne القديم.
- إذا كان ARCO هو المرجع الموجود والمقبول، سجّل ألوانه المحايدة ولمسته الحمراء. لا تخترع هوية لونية إن لم توجد مراجع فعلية.

## 5. قيّم المسارات والبيانات

قارن الموجود مع قائمة المسارات في `docs/ROUTE_MAP_AR.md`، وحدد:
- المسارات الموجودة والناقصة والمتعارضة.
- هل صفحات أسواق كوريا والسعودية واليمن تستخدم منطقاً مشتركاً أم تكراراً؟
- هل صفحة السيارة منفصلة بمسار غير متعارض مثل `/car/:slug`؟
- هل توجد قاعدة بيانات سيارات typed أو بيانات تجريبية؟
- هل أكواد KR/SA/YE فريدة؟
- هل الأسعار ومصدر الصرف واضحان؟
- هل بيانات الهاتف وWhatsApp والعناوين مصدرها إعداد موثوق أم placeholders؟

## 6. افحص السلامة والأداء

تحقق من:
- تشغيل مكتبات تعتمد `window` و`document` داخل SSR.
- تكرار محركات الحركة أو تداخل `transform` بين GSAP وMotion.
- اعتراض scroll أو wheel أو touch.
- صور خارجية مكسورة أو صور سيارات غير مطابقة للموديل.
- شعارات علامات غير أصلية.
- أرقام اتصال أو تقييمات أو تقارير فحص أو أسعار تبدو حقيقية دون مصدر.
- analytics أو pixels أو session recording أو cookies غير مصرح بها.

## 7. المخرجات المطلوبة

أخرج تقريراً منظماً يتضمن:
1. ملخص حالة المشروع والتقنية الفعلية.
2. جرد المسارات والمكونات والبيانات والأصول.
3. جرد Packages مع بيان وظيفة كل واحدة وما إذا كانت مستخدمة.
4. التعارضات ومخاطر SSR/RTL/الحركة والصور والخصوصية.
5. الفجوات مقارنة بخريطة الصفحات والمعايير.
6. خطة تنفيذ مرتبة بالمراحل 01–08، مع الملفات المتوقع تعديلها في كل مرحلة.
7. اقتراح الحزم التي قد نحتاج إضافتها، مع تبرير لكل واحدة وعدم إضافة المكرر.
8. قرارات تحتاج بيانات حقيقية من الشركة (هواتف، WhatsApp، بريد، عناوين، صور، أسعار، تقارير).

**شرط التوقف:** لا تعدّل الكود، لا تثبّت Packages، ولا تبدأ المرحلة 01 قبل عرض التقرير. لا تتجاوز النواقص باختلاق بيانات.
